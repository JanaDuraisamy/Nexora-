# Infrastructure — Supabase / PostgreSQL

Phase 0 hosts on **Supabase Cloud**, but the schema stays plain PostgreSQL:
extension-free, schema-qualified, and portable to any PostgreSQL 15+ instance.

## Layout

```
infra/supabase/
├── migrations/
│   ├── 20261031000100_init.sql         # schema, tables, indexes, event guards
│   └── 20261031000200_permissions.sql  # grants, has_permission(), RLS
├── seed.sql                            # reference identities and Phase 0 grants
└── config.toml                         # generated by `supabase init` (not committed yet)
```

`config.toml` is intentionally not hand-written. Generate it with the Supabase
CLI so the local ports and settings match the installed CLI version.

## First-time setup

```bash
# From the repository root
npm install --global supabase        # or use npx

# From infra/ so config.toml lands in infra/supabase/
cd infra
supabase init                       # creates supabase/config.toml
supabase start                      # local stack (Postgres on 54322 by default)
supabase db reset                   # apply migrations + seed.sql
```

If `supabase init` refuses because `infra/supabase` already exists, run it in a
temporary directory and copy only the generated `config.toml` here. Do not
overwrite the migrations.

## Cloud deployment

```bash
cd infra
supabase link --project-ref <project-ref>   # project ref is not a secret
supabase db push                            # migrations only
psql "$SUPABASE_DB_URL" -f supabase/seed.sql # optional: first bootstrap only
```

Never commit the database password, service role key, or connection string.
The service role key belongs only in the Core API server environment.

## Local connection string

```
postgresql://postgres:postgres@127.0.0.1:54322/postgres
```

Set `DATABASE_SSL=disable` for the local stack and `DATABASE_SSL=require` for
Supabase Cloud.

## Verification

The migrations and seed have been executed against **PostgreSQL 18.6** via
`@electric-sql/pglite` (a WebAssembly build of PostgreSQL). That run covered:

- both migrations applied cleanly, in order;
- `seed.sql` applied twice — 5 identities and 20 grants, second run idempotent;
- owner-tier bypass, EV task write, ELIO read-only, revoked grant denied;
- task insert at `v1/backlog`, optimistic version increment, event `seq = 1`;
- `UPDATE` and `TRUNCATE` on `nexora.events` rejected by the append-only trigger;
- a decision cannot be approved without a decider;
- `nexora.current_actor_id()` resolves the Supabase JWT claim.

What is **not** verified yet:

- application to Supabase Cloud (`supabase db push`) — needs a project ref and
  credentials from Jana;
- Supabase-hosted Auth JWT enforcement and pooler behaviour;
- an HTTP API end-to-end run against a live PostgreSQL instance.

Those remain tracked in `docs/specs/phase-0-foundation.md` under remaining work.
